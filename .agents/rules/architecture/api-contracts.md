# Контракты API и SSE

Обязательное правило при изменении запросов к backend.

- Канонические серверные контракты — `../../../../backend/openspec/specs/system/rest-api/spec.md`.
- Клиентский mapping, модели, пагинация, преобразования и ошибки — `openspec/specs/frontend/client-api-mapping/spec.md`.
- База URL и заголовок identity — `../development/conventions.md`, раздел «HTTP и API».
- Не переименовывай существующие пути, параметры и поля без согласования с backend.
- Изменения делай аддитивными; новые поля не должны ломать текущие ответы.
- Не описывай нереализованный клиентский метод как работающий.
- Различай отсутствие endpoint на сервере и незавершённую клиентскую реализацию.
- Не объявляй структуру SSE payload, имена событий, порядок, reconnect и гарантии доставки контрактом, пока они не определены в backend Spec или отдельной integration Spec.
- При расхождении backend Spec, frontend Spec и кода остановись, зафиксируй источники и запроси решение у пользователя.
