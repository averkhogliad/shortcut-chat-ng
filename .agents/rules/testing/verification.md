# Проверка изменений

Объём проверки выбирай соразмерно риску. Полную проверку для мелкой правки не запускай.

## Команды

- Сборка: `npm run build` (`ng build`, production-конфигурация по умолчанию).
- Тесты: `npm test` (`ng test`, Karma + Jasmine).

Других подтверждённых команд проверки нет.

## Выбор проверки

- Только документация или правила — проверка приложения не нужна.
- Локальная правка без изменения поведения (типы, имена, текст) — достаточно `npm run build`.
- Изменение поведения компонента, сервиса, guard, interceptor или модели — `npm run build` и релевантные specs через `npm test`.
- Изменение конфигурации сборки, окружений или зависимостей — `npm run build`; при риске для тестов дополнительно `npm test`.
- Не запускай весь набор тестов, если можно ограничиться затронутыми файлами. Готового фильтра Karma в проекте нет; если ограничить нельзя, зафиксируй это.

## Ограничения

- Нет lint, formatter и отдельного typecheck-скрипта.
- Нет e2e-конфигурации; README упоминает `ng e2e`, но target и зависимостей нет.
- Нет CI-конфигурации.
- `karma.conf.js` отсутствует: настройки в `angular.json`; headless-браузер и coverage явно не заданы.
- Существующие specs сгенерированы и не являются рабочим покрытием:
  - `app.component.spec.ts` обращается к отсутствующим `title` и `h1`;
  - specs `ChatPageComponent`, `ChatViewPageComponent`, `LoginPageComponent`, `TestPageComponent` не предоставляют обязательные DI-провайдеры;
  - `TestPageComponent` создаёт `EventSource` в конструкторе.
- `npm test` может упасть на компиляции или DI. Это ограничение тестовой инфраструктуры, а не доказательство ошибки в изменении.
- `@angular/cdk` импортируется без объявления в `package.json`; состояние `node_modules` может влиять на сборку.

## Правила отчёта

- Не утверждай, что проверка прошла, если команда не запускалась.
- Указывай точную команду и результат.
- Если проверка недоступна или упала по инфраструктурной причине, отделяй это от результата изменения.
