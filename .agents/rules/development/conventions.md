# Соглашения разработки

Обязательные соглашения проекта.

## Компоненты

- Соблюдай текущий стек и DI-механизм; не заменяй их без задачи.
- Компонент standalone; зависимости в `imports`, шаблон и стили через `templateUrl`/`styleUrl`.
- Не создавай `NgModule` и не переводи существующие компоненты на модульный стиль без задачи.
- Следуй стилю окружающего файла: импорты, именование, отступы, порядок членов класса.

## Состояние и данные

- Локальное состояние: `BehaviorSubject`, `signal`, `toSignal`; допускаются мутабельные аккумуляторы в компонентах.
- Не добавляй NgRx, Akita или собственный store без обоснования задачей.
- Модели — классы в `src/app/model/**`. Не превращай их в интерфейсы без необходимости.
- Формы преимущественно template-driven (`ngModel`, template refs). Reactive forms допустимы, если так проще в задаче.

## HTTP и API

- База URL — `environment.services.{users,chats,messages,notifications}`; не хардкодь адреса сервисов.
- Заголовок identity — `environment.security.header`; значение — `accountId` из principal.
- Production-значение `'/'` даёт пути вида `//users/...`; не считай его эталоном и не исправляй попутно.

## Стиль

- `.editorconfig`: UTF-8, 2 пробела, final newline, trim trailing whitespace; для TS — single quotes.
- Не переформатируй существующие файлы ради единообразия.
- Линтера, форматтера и typecheck-скрипта нет. Не выдумывай команды.

## Безопасные изменения

- Не делай несвязанный рефакторинг и массовое переформатирование.
- Не меняй поведение соседних функций ради «чистоты».
- Сохраняй незакоммиченные изменения. Перед правкой проверь `git status` и diff целевых файлов; не откатывай и не перезаписывай чужие правки.
- Не добавляй в правила, конфигурацию и код секреты, токены, пароли и реальные идентификаторы пользователей.
- Не создавай коммиты без явной просьбы.
- Не исправляй технический долг вне отдельной задачи.
